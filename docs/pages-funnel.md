작성: 얌얌(marketing) · 2026-09-10 · **설계 문서. 코드·카피 반영 없음.**

전제 문서 두 개를 읽고 그 위에서 판단했다. 어긋나는 결정은 §1에 전부 모았고, 조용히 바꾼 것은 없다.

- `docs/pages-architecture.md` (데이브) — URL 15개 · 콘텐츠 스키마 · 링크 계약
- `docs/detail-pages.md` (수진) — 템플릿 4종 · 블록 13개 · 여백 리듬

이 문서가 정하는 것: **페이지별 역할 / 랜딩 재정의 / 전환 동선 / 카피 슬롯 / 검색 의도.**

## 0. 먼저 읽을 다섯 줄 — 임팩트 순

| # | 지적 | 왜 이게 1순위인가 |
| --- | --- | --- |

### 문서 참조 불일치 하나

데이브 문서가 수진 문서를 `docs/pages-ui.md` 로 참조하는데 실제 파일명은 `docs/detail-pages.md` 다(수진 문서도 자신을 그 이름으로 부르지 않는다). 내용 충돌은 아니고 **참조 경로만 어긋난다.** 문서를 고칠 때 한쪽으로 통일하면 된다. 이 문서는 실제 파일명을 쓴다.

## 2. 페이지별 역할

각 페이지를 네 가지로 판정한다: **유입 경로 / 답해야 하는 의문 하나 / 다음 행동 / 없으면 잃는 것.**
등급은 전환 기여 기준이다 — **강함**(있어야 신청이 늘어난다) / **조건부**(값이 확정되면 강해진다) / **약함**(내부 구조 요구로만 존재) / **폐기**.

### 2.1 `/` 랜딩 — 강함

| | |
| --- | --- |
| 유입 | 브랜드 검색, 직접 입력, 명함·오프라인, 광고(도입 시) |
| 의문 | **"여기는 누구를 위해 무엇을 하는 곳인가"** |
| 다음 행동 | 대상 상세 3개 중 하나 · 또는 즉시 상담 |
| 없으면 | 전부 |

역할이 바뀐다. 지금은 "설득 + 신청"을 한 장에서 다 했다. 이제 **분류기**다 → §3.

### 2.2 `/coaching/adult` — 강함

| | |
| --- | --- |
| 유입 | 랜딩 `AudienceRows[0]` · 메가메뉴 `Adult` · 검색("커리어 전환 코칭", "이직 고민 상담") |
| 의문 | **"결정을 못 하는 게 정보 부족이 아니면 뭔가"** |
| 다음 행동 | `/consult?track=adult` (주) · `/program/weekly` (부) |
| 없으면 | 성인 트랙 유입 경로 전체. 랜딩 티저 3문장이 유일한 설명이 된다 |

### 2.3 `/coaching/senior` — 강함 (SEO 우선순위 1위)

| | |
| --- | --- |
| 유입 | 랜딩 · 메뉴 · 검색("은퇴 후 진로", "시니어 코칭", "퇴직 후 무엇을") |
| 의문 | **"은퇴하고 나서 코칭을 받는다는 게 뭘 하는 건가"** |
| 다음 행동 | `/consult?track=senior` |
| 없으면 | **가장 크게 잃는다.** 경쟁이 가장 얇고 검색 의도가 명확한 트랙인데 랜딩 티저 3문장으로는 그 의도를 받을 수 없다 |

이 페이지만 **본문 조판을 한 단 더 보수적으로** 간다. 수진 §7.3 기준(`.b2` 16/18 · 행간 180% · `--measure` 42rem)이 이미 시니어 기준으로 잡혀 있어 추가 요구는 없다. 다만 **CTA 를 페이지 안에서 두 번 만나게 한다** — 하단 `ConsultCta` 하나로는 스크롤 거리가 길다(§4.5).

### 2.4 `/coaching/leadership` — 강함

| | |
| --- | --- |
| 유입 | 랜딩 · 메뉴 · 검색("리더십 코칭", "팀장 처음", "관리자 교육") |
| 의문 | **"회사가 안 보내주는데 개인이 받을 수 있나"** — 이게 이 페이지의 진짜 의문이다 |
| 다음 행동 | `/consult?track=leadership` |
| 없으면 | B2B 를 제외한 상태에서 리더십 트랙을 설명할 곳이 없다 |

현재 카피에 이미 "회사를 거치지 않고 개인이 직접 신청할 수 있습니다"가 있다. **이 문장을 히어로 리드로 올린다.** B2B 제외가 약점이 아니라 포지션이 되는 지점 → §7.4.

### 2.5 `/program/weekly` — 조건부 강함 (가격 확정 시 강함)

| | |
| --- | --- |
| 유입 | 랜딩 `ProgramTabs` · 메뉴 `Weekly Coaching` · 대상 페이지 추천 카드 · 검색("1:1 코칭 비용", "코칭 가격") |
| 의문 | **"얼마고 몇 번이고 얼마나 걸리나"** |
| 다음 행동 | `/consult?track=program` |
| 없으면 | 가격·회차를 묻는 사람의 착지점. **거래 의도 검색을 받을 수 있는 유일한 페이지** |

**가격이 "상담 후 안내"면 이 페이지가 이탈 지점이 된다.** §9 O2.

### 2.6 `/program/diagnosis` — 중간

| | |
| --- | --- |
| 유입 | 랜딩 · 메뉴 · 대상 페이지 추천 카드 |
| 의문 | **"첫 세션에서 뭘 하나"** |
| 다음 행동 | `/consult?track=program` |
| 없으면 | 크게 잃지 않는다. 진단은 어차피 첫 단계라 상담 통화에서 설명된다 |

**하지만 원고 비용이 가장 싸다.** 「무엇을 정리하는지」 3~4단계가 곧 본문이고, 그 내용은 `/about` 의 코칭 3단계와 재료를 공유한다. 유지.

### 2.7 `/program/online` — 약함 (SEO 만이 근거) → C3

| | |
| --- | --- |
| 유입 | 검색("온라인 코칭", "화상 코칭", "비대면 코칭") · 메뉴 |
| 의문 | **"지방/해외에 살아도 되나"** |
| 다음 행동 | `/consult?track=program` |
| 없으면 | **지역 제약 없는 검색 유입 하나를 잃는다.** 그것만 잃는다 |

이 페이지가 "프로그램"인 척하면 방문자가 속는다 — Weekly 를 화상으로 하는 것이다. 유지한다면 **제목·본문을 "프로그램" 이 아니라 "원격으로 진행하는 방법"으로 쓴다.** 원고가 얇으면 `published:false` 로 두고 열지 않는다(데이브 §1.6 이 이미 그 경로를 만들어 뒀다).

### 2.8 `/coach` — **조건부 최상위**

| | |
| --- | --- |
| 유입 | 랜딩 `CoachBand` · 메뉴 `Coach` · `StoryTabs[review]` · 검색(코치 실명) |
| 의문 | **"이 사람에게 내 이야기를 해도 되나"** |
| 다음 행동 | `/consult` (트랙 없음) |
| 없으면 | **1:1 코칭에서 코치가 상품이다.** 신뢰 근거를 담을 유일한 페이지 |

지금 열 수 없다 — `김○○`, `○○ 코칭 자격 보유` 전부 플레이스홀더다. 데이브가 `published:false` 로 시작하기로 한 것이 맞다. **이력이 확정되는 순간 이 페이지가 전환 기여 1위가 된다.** §9 O1.

### 2.9 `/about` — 중간. 단 역할을 좁혀야 한다

| | |
| --- | --- |
| 유입 | 랜딩 `MidBanner`·`BrandStory`·`StoryTabs[practice]` · 메뉴 `Story` · 검색("코칭이란", "코칭 상담 차이") |
| 의문 | **"코칭이 상담·컨설팅·멘토링과 뭐가 다른가"** |
| 다음 행동 | 대상 상세 3개 중 하나 (상담이 아니다) |
| 없으면 | 코칭이라는 상품 자체를 모르는 사람을 받을 곳이 없다 |

**여기가 이 문서에서 가장 자주 오해되는 페이지다.** `/about` 을 "브랜드 이야기" 로 쓰면 전환 기여가 0에 가깝다 — 브랜드명도 미확정이고, 처음 온 사람은 브랜드에 관심이 없다. 이 페이지의 주 역할은 **코칭 방식 설명(Clarify · Practice · Review 3단계)** 이고 브랜드 서사는 그 뒤에 붙는 부차다.

수진 §5.1은 3단계를 ②에 두었다. **①로 올려야 한다** — C4와 같은 이유이며, `/about` 에서는 특히 그렇다. 정보 의도로 들어온 사람에게 브랜드 서사를 먼저 주면 첫 화면에서 나간다.

`/about` 의 다음 행동을 상담이 아니라 **대상 페이지**로 두는 이유: 코칭이 뭔지 방금 알게 된 사람은 아직 자기 트랙을 모른다. 상담으로 바로 보내면 대표의 첫 통화가 "어떤 걸 보고 오셨나요"가 된다 — 우리가 없애려는 바로 그 통화다. 단 `ConsultCta` 는 유지한다(막다른 페이지 금지).

### 2.10 `/faq` — 강함

| | |
| --- | --- |
| 유입 | 랜딩 `Faq` 섹션 「전체 보기」 · 메뉴 2곳 · 푸터 · `/consult` · 검색("코칭 효과", "코칭 비용", 롱테일) |
| 의문 | **"신청하기 전에 걸리는 게 하나 있다"** |
| 다음 행동 | `/consult` (트랙 없음) |
| 없으면 | 신청 직전 이탈 사유를 제거할 곳이 없다. 그리고 롱테일 검색 유입 전부 |

현재 FAQ 가 **4개뿐이다.** 페이지 한 장은 10개 이상이 필요하다(수진 §5.3이 "10개를 넘으면 카테고리로 묶는다"고 전제한 규모). 원고 요구 → §9 O5.

### 2.11 `/service` — **폐기 제안** → C2

| | |
| --- | --- |
| 유입 | 랜딩 `Services` 섹션 · 메뉴 `Service` · 푸터 |
| 의문 | **없다.** "서비스가 뭐가 있나요"는 사용자가 하지 않는 질문이다 |

항목 4개를 하나씩 보면 답이 안 나온다.

| 항목 | 실제 정체 | 갈 곳 |
| --- | --- | --- |
| `Free Consulting` | 서비스가 아니라 **CTA** | `/consult` 페이지 자체 |
| `Session Note` | 프로그램 **포함 사항** | `/program/weekly` 의 `included` 슬롯 (데이브 §2.4.2에 이미 있다) |
| `Group Session` | **운영 여부 미확정** (DEVNOTE §6) | 확정 전까지 목적지 없음 |
| `After Care` | **운영 여부 미확정** (DEVNOTE §6) | 확정 전까지 목적지 없음 |

4칸 중 2칸이 존재 미확정이다. **존재하지 않을 수도 있는 것으로 페이지 한 장을 채울 수 없다.** 그리고 채운다면 지어내는 것이다.

**랜딩 `Services` 섹션은 유지한다.** 4칸 그리드가 수진 레이아웃 리듬에 묶여 있고, "코칭 받으면 뭐가 딸려 오나"를 한눈에 주는 값은 있다. 링크 목적지만 재배정한다(§3.2). 메뉴·푸터의 `Service` 항목은 제거한다.

**대표가 그룹 세션·애프터케어를 실제로 운영한다고 확정하면 판단이 뒤집힌다** — 그때는 이 둘이 실제 상품이므로 `/service` 가 아니라 **`/program` 아래 항목**이 되는 게 맞다. §9 O4.

### 2.12 `/coaching` 인덱스 — 약함. 단 고유 기능 하나를 주면 유지 가치가 생긴다

| | |
| --- | --- |
| 유입 | 푸터 `Coaching` · 브레드크럼 중간 · 히어로 슬라이드2 CTA · 메가메뉴 그룹 제목 |
| 의문 | **"셋 중 어디에도 안 맞는 것 같은데"** ← 이걸 답하지 않으면 만들 이유가 없다 |
| 다음 행동 | 대상 상세 3개 · 또는 `/consult`(트랙 없음) |
| 없으면 | 브레드크럼 중간이 링크 없는 텍스트가 된다(수진 §4.3에 그 대안이 이미 적혀 있다) |

**솔직히 말하면 이 페이지는 랜딩 `AudienceRows` 와 같은 일을 한다.** 3개를 늘어놓고 고르게 하는 것. 랜딩에서 스크롤 한 번이면 도달하는 콘텐츠를 별도 URL 로 다시 만드는 셈이고, 근거는 전부 내부 구조 요구(브레드크럼·푸터 링크)이지 전환 요구가 아니다.

**유지하되 고유 기능 하나를 준다: 셋 중 어디에도 안 맞는 사람의 출구.**
랜딩에는 이 문장을 넣을 자리가 없다 — 랜딩은 셋을 병렬로 보여주는 화면이라 "해당 없음"을 말하면 흐름이 깨진다. 인덱스는 고르는 화면이므로 "모르겠으면 상담에서 함께 정한다"가 자연스럽다. 이게 있으면 페이지 하나 값을 한다.

원고 부담은 최소로: 히어로(제목+리드) + 카드 3개(티저 재사용) + 「해당 없음」 문단 1개 + CTA. 수진 T-C 그대로.

## 3. 랜딩의 역할 재정의

랜딩은 섹션 11개 + 상단 띠 배너다(`src/app/page.tsx` 기준).

### 3.1 랜딩은 이제 분류기다

한 문장으로: **랜딩은 "이게 당신 이야기다"까지만 말하고, "그래서 뭘 하는지"는 상세가 말한다.**

지금 랜딩은 설득과 신청을 한 장에서 다 하려 한다. 그래서 `AUDIENCES[].body` 가 4문장으로 상황과 방법을 모두 말하고 — **상세페이지를 볼 이유를 미리 없애 버린다.** 데이브 B8(랜딩 카피와 상세 카피 분리)이 승인되면 이 문장들이 갈라지는데, 그 갈라내는 기준이 §3.3이다.

### 3.3 어디까지 말하고 어디서 끊는가 — 규칙 3개

로보가 티저와 상세를 갈라 쓸 때의 기준이다.

**규칙 1. 랜딩 티저는 "누구의 어떤 상황"까지만 말한다. "어떻게 하는지"는 말하지 않는다.**

현재 `AUDIENCES[0].body` 를 보면 4문장이 이렇게 나뉜다.

```
"이직, 창업, 커리어 전환. 결정을 미루는 이유는 정보가 부족해서가 아니라
 기준이 정리되지 않아서입니다."                          ← 상황. 티저에 남긴다
"지금의 상황을 함께 펼쳐 놓고 무엇을 우선할지부터 정합니다." ← 방법. 상세로
"코치가 답을 드리는 대신, 스스로 답을 말할 수 있을 때까지 질문합니다." ← 방법. 상세로
```

티저는 2문장이면 된다. 남은 2문장은 `/coaching/adult` 의 `intro` 재료다. **이게 B8 이 실제로 요구하는 작업의 정체다** — 새로 쓰는 게 아니라 지금 문장을 갈라 놓고 각각을 늘리는 것.

**규칙 2. 숫자·가격·회차·기간은 랜딩에서 말하지 않는다.**

지금 `PROGRAM_CARDS[1].summary` 가 "주 1회 60분 1:1 세션"이라고 랜딩에서 말한다. 사양은 상세의 일이다(수진 T-B가 `SpecList` 를 본문 첫 블록으로 둔 이유). 랜딩에서 사양을 주면 상세를 열 이유가 사라지고, 반대로 사양이 미확정인 지금은 **랜딩에 잘못된 값이 박힐 위험**도 있다.

**규칙 3. 티저의 마지막 문장을 완결시키지 않는다.**

"…함께 정리합니다." 로 끝나면 답을 받은 것이다. "…무엇을 놓아도 되는지부터 정합니다" 처럼 **다음 질문이 남는 지점**에서 끊는다. 이건 낚시가 아니라 실제로 그 다음이 상세페이지에 있기 때문에 성립한다.

### 3.4 바로 상담 보낼 사람 vs 상세를 읽힐 사람

구분 장치는 **하나뿐이다: 랜딩 카드의 링크 목적지.** (수진 A11 이 물은 항목)

**답: 카드는 전부 상세로 돌린다.**

| | 잃는 것 | 얻는 것 |
| --- | --- | --- |
| 카드 → 상담 (현재) | — | 카드에서 바로 신청 |
| **카드 → 상세** (제안) | 정보 없이 하는 신청 경로 | ① 트랙이 URL로 식별된다 ② 상담 링크 4곳이 실제로 강조된다 ③ 상세 한 장을 읽고 온 신청이라 **첫 통화 품질이 올라간다** |

잃는 것이 실은 손실이 아니다. 카드만 보고 하는 신청은 대상·프로그램을 모르는 신청이고, 그 통화가 바로 대표가 없애고 싶어 하는 "어떤 걸 보고 오셨나요"다.

**이미 결정한 사람은 카드를 클릭하지 않는다.** 그 사람은 상단 배너를 보고 헤더 `Consult` 를 누르거나 히어로 CTA 를 누른다. 그 4개 경로는 항상 열려 있다. 구분은 사용자가 스스로 한다.

### 3.5 랜딩에서 없애도 되는 섹션 — 2건

**후보 1: `BrandStory`(8번) — 제거 권고.**

랜딩에 `/about` 로 가는 링크가 **3개**다: `MidBanner`(4) · `StoryTabs practice`(5) · `BrandStory`(8). 그리고 `MidBanner` 와 `BrandStory` 는 둘 다 풀블리드 다크 밴드이고 둘 다 `/about` 로 보낸다 — **같은 일을 두 번 한다.** `MidBanner` 는 사진+제목+본문+CTA 로 더 많은 일을 하고, `BrandStory` 는 워드마크와 밑줄 링크 한 줄이다.

제거하면: 스크롤 거리가 줄고, `/about` 진입점이 2개로 정리되고, 다크 밴드가 3개(MidBanner · BrandStory · Principles 오버레이)에서 2개로 줄어 대비 부채도 줄어든다(수진 §4.1이 지적한 스크림 재조정 4곳 → 3곳).

**단 이건 레이아웃 리듬 결정이다 — 수진 판정 항목으로 넘긴다.** 다크 밴드 배치가 페이지 실루엣을 만들고 있어서 전환만으로 결정할 수 없다.

**후보 2: `Services`(6번) 4칸 중 2칸 — 보류 권고.**

`Group Session` · `After Care` 는 운영 미확정이라 갈 곳이 없다(§2.11). 미확정인 서비스를 랜딩에 노출하고 클릭하면 상담으로 보내는 것은, 없는 상품을 팔고 상담에서 없다고 말하는 것이다. **운영 확정 전까지 카드 2개를 내린다.** 4칸 그리드가 2칸이 되면 레이아웃이 깨지므로 → 수진 판정.

**제거하지 않을 섹션 — `Principles`(9번).**

원칙 3개는 `/about` 로 흡수하는 게 내용상 맞다. 하지만 랜딩에서 빼면 **`ConsultSection` 직전의 마지막 블록이 FAQ 가 되고, 신청 버튼 앞에 신뢰 근거가 하나도 없어진다.** 지금 이 자리가 유일한 신뢰 블록이다(§7.2). 후기가 생기면 이 자리를 교체하는 게 맞고, 그때까지는 유지한다.

## 4. 전환 동선

### 4.1 `#consult` 11곳 → 트랙 4개 + 무트랙

**문제**: 페이지마다 상담 CTA 를 두면 대표는 어디서 온 신청인지 모른다. 첫 통화의 절반이 "어떤 걸 보고 오셨나요"로 낭비된다.

**해법의 함정**: track 값을 페이지마다 하나씩 만들면 13개가 된다. **값이 13개면 분류가 아니다.** 대표가 통화에서 실제로 쓸 수 있는 단위로 묶어야 한다.

**결론: track 은 4개 + 없음.**

| `track` | 어디서 붙는가 | 대표가 통화 시작 전에 아는 것 |
| --- | --- | --- |
| `adult` | `/coaching/adult`, 랜딩 `AudienceRows[0]` | 커리어 전환·이직 쪽 |
| `senior` | `/coaching/senior`, 랜딩 `AudienceRows[1]` | 은퇴 이후 설계 쪽 |
| `leadership` | `/coaching/leadership`, 랜딩 `AudienceRows[2]` | 팀·조직 쪽 |
| `program` | `/program/*` 3개, `/program` 인덱스 | **가격과 회차를 이미 봤다** |
| (없음) | 랜딩·헤더·푸터·메뉴·`/about`·`/coach`·`/faq`·`/consult` 직접 | **아직 트랙을 안 정했다** |

**프로그램 3개를 쪼개지 않는 이유.** "진단 세션 보고 오셨나요, 주간 코칭 보고 오셨나요"는 통화에서 의미가 없다 — 진단은 어차피 첫 단계다. 대표에게 필요한 정보는 **"가격을 봤는지"** 하나이고 `program` 하나로 충분하다.

**무트랙을 억지로 채우지 않는 이유.** 값이 없는 것도 정보다 — "아직 트랙을 안 정한 사람"이라는 정보이고, 그 통화는 트랙을 정하는 통화로 시작하면 된다. `/about` 이나 `/faq` 에 억지로 트랙을 붙이면 잘못된 정보가 된다.

값 4개는 데이브 §3.3의 서버 화이트리스트에 그대로 들어간다. `AudienceSlug` 닫힌 유니온 3개 + `"program"` 하나다.

### 4.2 폼 필드는 늘리지 않는다 — 대신 placeholder 를 바꾼다

**필드 추가 제안 없음.** 현재 4개(이름 · 연락처 · 희망 시간 · 고민되는 점) + 동의 체크박스를 유지한다. track 은 hidden 이다(데이브 §3.4 그대로).

**"어떤 걸 보고 오셨나요"를 완전히 없애려면 track 만으로는 부족하다** — track 은 "무엇에 관심 있나"만 알려주고 "무엇을 읽었나"는 모른다. 그렇다고 "어떤 페이지를 보셨나요" 필드를 만들면 전환이 떨어진다. **필드 수를 그대로 두고 응답 품질을 올리는 가장 값싼 방법이 placeholder 다.**

| track | 「고민되는 점」 placeholder |
| --- | --- |
| `adult` | 지금 걸려 있는 결정 하나만 적어 주세요 |
| `senior` | 은퇴 시점, 하고 싶은 일, 지금 걸리는 것 중 하나만 적어 주세요 |
| `leadership` | 팀에서 가장 자주 막히는 장면 하나를 적어 주세요 |
| `program` | 어느 프로그램을 보셨는지, 묻고 싶은 것 하나를 적어 주세요 |
| (없음) | 지금 어떤 상황인지 한두 문장으로 적어 주세요 |

필드는 그대로 4개이고 입력 장벽은 오히려 낮아진다("한 문장"으로 범위를 좁혀 주기 때문에). `program` 트랙에서만 어느 프로그램인지 자연스럽게 회수된다 — 필드를 늘리지 않고 정보를 얻는다.

**「상담 희망 시간」 필드는 유지 판단.** 없애면 조율 왕복이 한 번 늘고, 그 왕복이 신청 후 이탈을 만든다. 필수가 아니라 선택 필드이므로 전환 손실이 없다.

### 4.3 각 페이지에서 상담까지 클릭 수

| 출발 | 경로 | 클릭 |
| --- | --- | --- |
| 랜딩 (끝까지 스크롤) | `ConsultSection` 폼 직접 | **0** |
| 랜딩 (어디서든) | 헤더 `Consult` → `/consult` | **1** |
| `/coaching/*` | 하단 `ConsultCta` → `/consult?track=` | **1** |
| `/program/*` | 하단 `ConsultCta` | **1** |
| `/about`, `/coach`, `/faq` | 하단 `ConsultCta` | **1** |
| 인덱스 2개 | 하단 `ConsultCta` | **1** |
| `/privacy` | (CTA 없음) 푸터 「무료 상담 신청」 | **1** |
| 랜딩 → 대상 상세 → 상담 | 카드 → `ConsultCta` | **2** |
| 랜딩 → 대상 상세 → 프로그램 상세 → 상담 | 최장 경로 | **3** |

**전부 3클릭 이내. 문제 없다.** 제출은 클릭 수에 포함하지 않았다(모든 경로에 +1).

최장 3클릭 경로(대상 → 프로그램 → 상담)는 **오히려 가장 좋은 신청**이다 — 트랙을 정하고 가격을 확인하고 오는 사람이다. 줄일 필요가 없다.

### 4.4 `/consult` 페이지와 랜딩 앵커의 역할 분리

데이브 B3(둘 다 둔다)를 지지한다. 단 **같은 화면을 두 번 두는 게 아니다.**

| | 랜딩 `#consult` | `/consult` |
| --- | --- | --- |
| 오는 사람 | 랜딩을 끝까지 스크롤한 사람 | 상세페이지에서 온 사람 · 헤더·메뉴·푸터에서 온 사람 |
| 그 사람의 상태 | 섹션 10개를 읽었다. **이탈 사유가 이미 제거됐다** | 한 페이지만 읽었거나 아무것도 안 읽었다. **"지금 신청해도 되나"가 남아 있다** |
| 화면 구성 | 좌측 연락처 + 우측 폼 (현재 그대로) | **폼 위에 이탈 사유 제거 블록** + 폼 |
| 폼 컴포넌트 | 공유 | 공유 |
| 데이터 | `pages.consult` 하나 | 같음 |

**`/consult` 의 이탈 사유 제거 블록 — 4줄.** 전부 이미 확인된 사실이라 지어내는 것이 없다.

| 슬롯 | 내용 | 출처 |
| --- | --- | --- |
| 1 | 첫 상담은 무료다 | `TOP_MESSAGES`, `FAQS[3]` |
| 2 | **하루 안에 연락한다** | `TOP_MESSAGES[0]` — 지금 상단 배너에만 있다. **검증 가능한 운영 약속이므로 여기로 올린다** |
| 3 | **시작하지 않아도 진단 결과는 안내한다** | `FAQS[3]` 뒷문장. **강매 없음을 말하는 가장 값싼 방법.** 지금 FAQ 아코디언 안에 접혀 있어 아무도 안 본다 |
| 4 | 수집 항목과 파기 시점 + `/privacy` 링크 | 동의 문구 (보안관 CONS-1~6과 글자 단위로 일치해야 한다) |

3번이 이 문서에서 제안하는 **가장 저비용 고효과 변경**이다. 이미 쓰여 있는 문장을 접힌 곳에서 전환 지점 바로 앞으로 옮기는 것뿐이다.

**`/consult` 하단에 `/faq` 링크 1개를 둔다.** 폼을 보고도 못 채운 사람의 유일한 출구다. 그 외 링크는 두지 않는다 — 전환 페이지에서 나가는 경로를 늘리지 않는다.

### 4.5 막다른 페이지 방지 — 페이지별 하단 구성

| 페이지 | `ConsultCta` (track) | `PageNav` (형제) | 교차 유도 | 페이지 중간 CTA |
| --- | --- | --- | --- | --- |
| `/coaching/adult` | ○ `adult` | 형제 대상 2 | 추천 프로그램 카드 2~3 | — |
| `/coaching/senior` | ○ `senior` | 형제 대상 2 | 추천 프로그램 카드 2~3 | **○ 1회** (아래) |
| `/coaching/leadership` | ○ `leadership` | 형제 대상 2 | 추천 프로그램 카드 2~3 | — |
| `/program/*` ×3 | ○ `program` | 형제 프로그램 2 | 대상 페이지 되돌림 (`forWhom`) | — |
| `/about` | ○ (없음) | — | 대상 3 카드 + `/coach` 1 | — |
| `/coach` | ○ (없음) | — | `/about` 1 | — |
| `/faq` | ○ (없음) | — | 답변 안 인라인 링크 | — |
| `/coaching` 인덱스 | ○ (없음) | — | 대상 3 카드 | — |
| `/program` 인덱스 | ○ `program` | — | 프로그램 3 카드 | — |

**막다른 페이지 0개.** `/privacy` 만 `ConsultCta` 가 없고, 수진 §6.4의 판단대로 보호책임자 연락처 블록이 그 자리를 대체한다 — 처리방침을 읽으러 온 사람에게 필요한 건 신청이 아니라 열람·정정·삭제 요청 경로다.

**`/coaching/senior` 에만 페이지 중간 CTA 를 하나 더 둔다.** 시니어 페이지는 본문 조판이 가장 길다(`.b2` 16/18 · 행간 180% · `--measure` 42rem). 하단 `ConsultCta` 까지 스크롤 거리가 다른 페이지보다 길어서, `process`(Steps) 직후에 `.lined` 링크 한 줄을 둔다. 버튼이 아니라 텍스트 링크다 — 읽는 흐름을 끊지 않는다. 문구는 §5.7.

### 4.6 모바일에서 CTA 도달 거리

| 경로 | 스크롤 |
| --- | --- |
| 랜딩 첫 화면 | 헤더 `Consult` 0 스크롤 · 히어로 CTA 0 스크롤 |
| 랜딩 → `ConsultSection` | 섹션 10개. **길다** — 그래서 카드 링크를 상세로 돌리는 게 맞다(§3.4). 상세로 들어가면 하단 CTA 가 훨씬 가깝다 |
| 상세페이지 | 헤더 `Consult` 0 스크롤 · 하단 `ConsultCta` 는 수진 실측 기준 페이지 1.5~2화면 |
| `/consult` | **0 스크롤로 폼 첫 필드 도달** — 이탈 사유 블록 4줄이 폼 위에 있으므로 모바일에서 첫 필드가 접힐 수 있다. 4줄을 **아코디언으로 접지 않는다**(접으면 아무도 안 본다). 대신 각 줄을 한 문장으로 제한한다 |

`/consult` 의 4줄이 모바일 첫 화면을 얼마나 먹는지는 **선우 실측 항목**이다. 폼 첫 필드가 접히면 블록을 폼 **아래**로 내리는 것보다 **줄 수를 3개로 줄이는 것**이 맞다(2·3번이 우선, 1번은 상단 배너와 중복).

## 5. 페이지별 카피 구조와 슬롯

로보가 그대로 채울 수 있게 슬롯 이름을 **데이브 스키마 필드명**으로 쓰고, 순서는 **수진 템플릿 블록**에 맞췄다. 예시는 형태만 보여주며, 값이 미확정인 곳은 `[대표 확인 필요]` 로 표시했다.

### 5.0 모든 페이지 공통 규칙

| 슬롯 | 분량 | 역할 |
| --- | --- | --- |
| `hero.title` | **12~18자** (수진 경고 26자) | 페이지 제목. 세리프 `.t1` |
| `hero.lead` | **60~90자, 3줄 이내** (수진 경고 110자) | **읽을지 말지가 여기서 결정된다.** "누구에게 무엇을"을 한 문장에 담는다 |
| 첫 본문 블록 | — | **자기 확인.** 산문이 아니라 목록·사양 (C4) |
| `cta.heading` / `cta.body` | 제목 12~18자 / 본문 40~70자 | 행동 지시 |

**`hero.lead` 작성 규칙 하나**: 브랜드명을 쓰지 않는다. 미확정이고, 처음 온 사람은 브랜드에 관심이 없다. 대신 **"당신"의 상황**으로 시작한다.

### 5.1 T-A 대상별 3개 — `/coaching/{adult|senior|leadership}`

수진 T-A 순서를 C4대로 재배열했다. 데이브 슬롯명 기준.

| 순서 | 슬롯 | 블록 | 분량 | 역할 | 예시 한 줄 |
| --- | --- | --- | --- | --- | --- |
| — | `hero.title` | `PageHeader` | 12~18자 | 이 페이지가 다루는 상황 | 「경험을 다음 시간에 쓰는 법」 (현 `AUDIENCES[1].title` 재사용 가능) |
| — | `hero.lead` | | 60~90자 | 누구에게 무엇을 | 「은퇴는 끝이 아니라 역할이 바뀌는 지점입니다. 무엇이 남고 무엇을 놓아도 되는지부터 함께 정합니다.」 |
| ① | `signals` | `SectionRow` + `.list-dot` | 제목 1줄 + **4~6줄**, 각 줄 15~30자 | **자기 확인.** 스크롤 없이 "내 이야기다" | 제목: 「이런 상황이라면」 / 항목: 「퇴직 시점은 정해졌는데 그 다음이 안 그려진다」 |
| ② | `intro` | `SectionRow` 산문 | **문단 2~3개**, 각 100~200자 | 그래서 무엇을 하는가 | 제목: 「무엇을 정리하는 시간인가」 / 첫 문단은 규칙 1에 따라 랜딩 티저에서 갈라낸 방법 문장으로 시작 |
| ③ | `process` | `Block` + `Steps` | **3~4스텝**, 제목 10~14자 + 본문 40~50자 | 어떻게 진행하나 | 「첫 세션에서 상황을 펼친다」 / 「지킬 수 있는 크기로 잘라 실행한다」 / 「막힌 지점을 확인하고 다시 맞춘다」 |
| ③' | (중간 CTA) | `.lined` 링크 1줄 | — | **`senior` 만** (§4.5) | 「지금 상황부터 이야기해 보기」 |
| ④ | `facts` | `Block` + `SpecList` | **4행** | 조건 확인 | 대상 / 진행 형태(대면 또는 화상) / 진행 주기 `[대표 확인 필요]` / 비용 `[대표 확인 필요]` |
| ⑤ | `recommendedPrograms` | `Block` + `CardGrid` | **2~3개 참조** | 다음 결정 | `adult`·`leadership` → `["diagnosis","weekly"]` / `senior` → `["diagnosis","weekly"]` |
| ⑥ | `faqTags` | `Block` + FAQ 3 | 태그 참조 | 신청 직전 이탈 사유 제거 | `["audience:senior","general"]` |
| ⑦ | — | `PageNav` | 자동 | 형제 대상 2 | |
| — | `cta` | `ConsultCta` | 제목 12~18자 + 본문 40~70자 | 전환 | 제목: 「먼저 이야기부터 들려주세요」 / 본문: 「첫 상담은 무료입니다. 하루 안에 연락드립니다.」 |

**`detail` 슬롯은 비운다.** 데이브 스키마에 있지만 쓰지 않는다(비우면 섹션이 렌더되지 않는다 — 데이브 §1.3 B안의 설계 그대로). 이유: `intro` 와 `detail` 두 산문 블록을 채우면 페이지당 문단이 12~16개가 되고, 수진 산정(문단 6~8개)의 두 배다. **원고가 없는 슬롯은 비워 두는 것이 지어내는 것보다 낫다.** 스키마 변경은 필요 없다.

**페이지별 차이는 슬롯 개수로만 표현한다** (데이브 §1.3의 variation 방식):

| | `signals` | `process` | `facts` | 중간 CTA |
| --- | --- | --- | --- | --- |
| `adult` | 4~5줄 | 3스텝 | 4행 | × |
| `senior` | **6줄** (상황이 다양하다) | 4스텝 | 4행 | **○** |
| `leadership` | 4~5줄 | 3스텝 | 4행 | × |

`leadership` 만 `hero.lead` 에 **"회사를 거치지 않고 개인이 직접 신청할 수 있다"** 를 넣는다(§7.4).

### 5.2 T-B 프로그램 3개 — `/program/{diagnosis|weekly|online}`

수진 T-B 순서를 그대로 따른다. `SpecList` 를 본문 첫 블록으로 두는 판단이 맞다 — 이 페이지 방문자의 첫 질문은 "얼마 · 몇 번 · 어떻게"다.

| 순서 | 슬롯 | 블록 | 분량 | 예시 한 줄 |
| --- | --- | --- | --- | --- |
| — | `hero.title` | `PageHeader` | 12~18자 | 「주 1회, 실행을 점검하는 시간」 |
| — | `hero.lead` | | 60~90자 | 「세션에서 정한 것을 실제로 해보고, 막힌 지점을 다음 세션에서 다시 맞춥니다.」 |
| ① | `facts` | `Block` + `SpecList` | **6행** | 아래 별도 표 |
| ② | `intro` | `SectionRow` 산문 | **문단 2개** | 제목: 「이 프로그램은」 |
| ③ | `process` | `Block` + `Steps` | **3~5스텝** | 「일정을 잡는다」 → 「세션을 진행한다」 → 「기록을 받는다」 → 「다음 목표를 정한다」 |
| ④ | `included` | `SectionRow` + `.list-dot` | **3~5줄** | 「세션마다 정리한 내용과 다음까지 할 일을 기록으로 드립니다」 ← 랜딩 `Session Note` 에서 이관 |

**`facts` 6행 — 가격 표기가 이 페이지의 승부처다.**

| 라벨 | `weekly` 예시 값 |
| --- | --- |
| 대상 | 방향을 정하고 실행을 점검할 사람 |
| 형식 | 1:1 · 대면 또는 화상 |
| 회차 | `[대표 확인 필요]` |
| 진행 | 세션 기록 제공 |
| **비용** | **「무료 상담에서 회차와 함께 안내드립니다」** ← "상담 후 안내" 가 아니다 |
| 신청 | 무료 상담 후 일정 조율 |

**"상담 후 안내"를 그대로 쓰지 않는 이유.** 같은 정보인데 「상담 후 안내」는 **거절**로 읽히고(가격을 숨긴다) 「무료 상담에서 회차와 함께 안내드립니다」는 **다음 행동**으로 읽힌다. 회차가 정해지지 않으면 총액을 말할 수 없다는 사실을 설명하기 때문에 정직하기도 하다. **다만 이건 완화이지 해결이 아니다** — 가격 확정이 필요하다(§9 O2).

**`/program/online` 은 슬롯 구성을 바꾼다** (C3). "프로그램" 이 아니라 "원격 진행 방법" 이므로:

| 순서 | 슬롯 | 내용 |
| --- | --- | --- |
| ① | `facts` | 3행만 (형식 / 사용 도구 `[대표 확인 필요]` / 시차·지역 제약) |
| ② | `intro` | 「대면과 무엇이 같고 무엇이 다른가」 문단 2개 |
| ③ | `process` | 「연결 방법」 3스텝 |
| ⑤ | `notes` | 「대면으로 바꾸고 싶어지면」 — `FAQS[2]` 에 이미 답이 있다 |
| ⑥ | `forWhom` | **`/program/weekly` 1개로 되돌림** — 온라인은 Weekly 의 진행 형태이므로 |

`hero.title` 에 "온라인 코칭"을 쓰되 `hero.lead` 첫 문장에서 **Weekly 와 같은 세션이라는 것을 명시**한다. 그러지 않으면 별개 상품으로 오해되고, 오해한 상태로 신청하면 통화에서 정정해야 한다.

- 진행 방식: 세션이 몇 분인지 / 기록을 어떤 형태로 받는지 / 중간에 그만둘 수 있는지

**기존 4개는 전부 유지한다.** 특히 `FAQS[3]`("상담 후 프로그램을 시작하지 않아도 진단 결과는 그대로 안내드립니다")은 **강매 없음을 말하는 유일한 문장**이고 `/consult` 로도 올린다(§4.4).

### 6.1 제목·설명의 방향 (실제 문구는 로보)

**`title`**: `{상황 또는 대상} 코칭 — {한 줄 약속}`. 브랜드명은 데이브 §4.1의 `title.template` 이 붙이므로 **제목에 직접 쓰지 않는다.**

- 좋음: `시니어 코칭 — 은퇴 이후를 스스로 설계하는 1:1 코칭`
- 나쁨: `성인 시니어 리더십 코칭 커리어 전환 은퇴 설계 | 코칭` ← 나열

**`description`**: **1문장 상황 + 1문장 다음 행동.** 두 번째 문장에 **「첫 상담 무료」를 넣는다** — 검색 결과 클릭률에 직접 기여하는, 지금 확정된 유일한 사실이다.

- 예: `은퇴 시점은 정해졌는데 그 다음이 안 그려지는 분을 위한 1:1 코칭입니다. 첫 상담은 무료이고, 하루 안에 연락드립니다.`

**금지**: 같은 키워드를 title·description·h1 에 세 번 반복. 페이지 3개의 description 을 한 문장만 바꿔 복제.

### 6.2 데이브 색인 설계에 대한 지적 하나

데이브 §1.1 표는 15개 라우트 전부 `index: ○` 다. 전환·SEO 관점 지적:

**인덱스 2개(`/coaching`, `/program`)가 랜딩과 콘텐츠가 겹친다.** 둘 다 "카드 3개 나열"이고 랜딩의 `AudienceRows`·`ProgramTabs` 와 같은 내용이다. 랜딩이 훨씬 강한 페이지이므로 **인덱스가 랜딩의 순위를 갉아먹을 수 있다**(카니발라이제이션).

색인 제외까지는 하지 않는다 — 브레드크럼과 내부 링크 목적지로 필요하고, 색인에서 빼면 그 링크의 값도 사라진다. 대신 **두 가지**를 한다.

1. **`sitemap` priority 를 낮춘다.** 데이브 표의 `0.8` → **`0.5`**. 대상·프로그램 상세(`0.9`)와 랜딩(`1.0`) 아래로 명확히 내린다.
2. **인덱스 카피를 랜딩 티저와 완전히 다르게 쓴다.** B8 이 이미 요구하는 것이고, 인덱스에서는 특히 §5.6의 「어디에 해당하는지 모르겠다면」 문단이 랜딩에 없는 고유 콘텐츠가 된다.

`/consult` 색인은 유지한다. 브랜드 쿼리에서 폼 페이지가 뜨는 것은 전환 최단거리라 나쁘지 않다.

## 7. 빠진 것

### 7.1 사례·후기 — **지금이 담을 시점이다. 그런데 담을 것이 없다**

이전에 내가 지적한 두 항목(사례·후기 섹션 부재 / 코치 신뢰 요소 약함)을 페이지가 생기는 지금 판정한다.

**자리는 생겼다.** 후기가 있다면 놓을 곳이 세 군데다.

| 자리 | 무엇을 놓나 | 전환 기여 |
| --- | --- | --- |
| `/coach` ①과 ② 사이 | 이 코치와 한 세션에 대한 후기 1~2개 | **최상.** 코치가 상품이다 |
| `/coaching/{slug}` ③과 ④ 사이 | 그 대상의 후기 1개 | 높음. "나 같은 사람이 받았다" |
| 랜딩 `Principles` 자리 | 짧은 후기 3개 | 높음. 폼 직전 마지막 블록(§3.5) |

**그런데 후기가 0개다. 그리고 지어낼 수 없다.**

**제안: 데이브 스키마에 `testimonials` 슬롯을 추가하지 말자.**

근거는 데이브 자신이 §2.4.2에서 환불 규정에 대해 쓴 논리 그대로다 — **"슬롯을 미리 만들어 두면 누군가 지어낸 문구를 채운다."** 후기 슬롯은 그 위험이 특히 크다. 관리자 폼에 「후기」 필드가 비어 있으면 채우고 싶어진다.

**대신 대표에게 실제 자료를 요청한다** (§9 O3). 기존 코칭 경험이 있다면 필요한 것은 이것뿐이다.

- 대상별 익명 후기 1개씩 (3개) — 실명 없이 「50대 · 은퇴 준비」 수준의 식별만
- 각 후기의 **게시 동의** (개인정보다. 보안관 검토 필요)
- 없으면 없다고 말해 주는 것 — 그러면 §7.2로 간다

자료가 오면 그때 슬롯을 추가한다. **스키마 변경 비용은 1회이고, 그 1회가 지어낸 후기 하나보다 훨씬 싸다.**

### 7.2 후기가 없어도 지금 넣을 수 있는 신뢰 근거 — 4개

전부 **대표가 답만 하면 되는 사실**이고 창작이 아니다. 후기가 안 나올 경우 이게 대안이다.

| # | 근거 | 어디에 | 필요한 것 |
| --- | --- | --- | --- |
| **1** | **코치 자격·경력** | `/coach` `credentials` | 실제 자격증 이름과 연수 `[대표 확인 필요]` — §9 O1 |
| **2** | **세션 노트 실물** | `/program/weekly` `included` · 랜딩 `Services` | **양식 이미지 1장.** "기록으로 남긴다"를 말이 아니라 물건으로 보여준다. 개인정보가 없는 빈 양식이면 되므로 **오늘 만들 수 있다** |
| **3** | **연락 시간 약속** | `/consult` | 「하루 안에 연락」이 지금 상단 배너에만 있다. **검증 가능한 운영 약속**이므로 전환 지점으로 올린다(§4.4) |
| **4** | **강매 없음 명시** | `/consult` | `FAQS[3]` 뒷문장을 아코디언 밖으로 꺼낸다. **비용 0, 효과 큼** |

2번이 특히 값어치가 높다. 사진 촬영 계획(수진 A5)이 미정인 상태에서 **유일하게 지금 확보 가능한 실물 이미지**다.

### 7.3 페이지 공개 전에 반드시 붙어야 하는 것 — 폼 전송

§0 1번과 C1의 근거를 여기에 정리한다.

지금 `ConsultForm` 은 600ms 대기 후 「상담 신청이 접수되었습니다 / 하루 안에 연락드립니다」를 띄운다. **DB·알림 없이.**

페이지 13개를 만들고 CTA 를 20곳에 심고 검색 색인까지 들어간 상태에서 폼이 안 가면:

- 신청자는 하루를 기다린다 → 연락이 안 온다 → 두 번째 기회가 없다
- 대표는 신청이 0건이라고 생각한다 → **페이지 작업이 실패한 것으로 판단한다**
- 유실된 신청은 **복구할 수 없다.** 이 프로젝트에서 되돌릴 수 없는 유일한 손실이다

데이브 §5.2 표에서 폼 전송은 S8(관리자)에 있고, 페이지 콘텐츠 채우기는 S6이다. **S6 에서 `published:true` 로 넘기기 전에 폼 전송이 동작해야 한다.** 순서를 이렇게 본다.

```
S4 라우트 골격 (published:false, 색인 안 됨)   ← 지금 상태로 안전
S5 링크 전환                                    ← 안전
★  폼 전송 + 저장 + 알림                        ← 여기로 당긴다
S6 콘텐츠 채우기 → published:true               ← 여기서 처음 위험해진다
```

보안관이 이미 찾은 배포 차단급 문제("Vercel 서버리스는 파일시스템이 읽기 전용이라 JSON 어댑터가 동작하지 않는다 — 최악은 폼이 '접수되었습니다'를 띄우면서 데이터가 사라지는 것")와 **정확히 같은 문제**다. 보안관은 배포 관점에서, 나는 페이지 공개 관점에서 같은 결론에 왔다.

**임시 조치 하나**: 폼 전송이 붙기 전에 페이지를 열어야 하는 사정이 생기면, 완료 화면 문구를 「접수되었습니다」에서 **전화번호 안내**로 바꾼다. 거짓말을 하지 않는 것이 우선이다.

### 7.4 B2B 제외가 페이지 구성에 미치는 영향

영향받는 페이지는 **`/coaching/leadership` 하나뿐이다.**

**잃는 것**: 기업 담당자 유입 경로. 데이브 §1.3이 예시로 든 "리더십 페이지 `facts` 에 기업 담당자 문의 항목"은 **넣지 않는다**(C6). 받을 곳이 없는 문의를 유도하면 대표가 답할 수 없는 연락이 온다.

**얻는 것 — 이게 더 크다. 차별점이 된다.**

리더십 코칭은 보통 회사가 사주는 상품이고, **개인이 자기 돈으로 사는 경로가 드물다.** 그래서 검색 의도가 갈린다.

| 쿼리 | 찾는 사람 | 우리 |
| --- | --- | --- |
| 「리더십 코칭」 「임원 코칭」 | 기업 HR · 교육 담당자 | **받지 않는다** |
| 「팀장 처음」 「관리자 코칭 개인」 「리더십 코칭 개인 신청」 | 회사 예산 없이 자기 돈으로 찾는 팀장 | **여기가 우리 자리다** |

현재 카피에 이미 답이 있다 — `AUDIENCES[2].body` 의 "회사를 거치지 않고 개인이 직접 신청할 수 있습니다". 이 문장이 지금 4문장짜리 티저의 **맨 마지막**에 있어 아무도 못 본다. **`hero.lead` 로 올린다.**

**리스크와 대응**: 기업 문의가 오면 폼의 「고민되는 점」으로 들어온다. 필드를 늘리지 않고, 문의가 실제로 쌓이면 그때 B2B 를 연다. 그 판단 자체가 데이터가 된다.

**나머지 12개 페이지는 영향 없다.** B2B 를 제외해서 페이지 구성이 달라지는 곳은 없다 — 애초에 전부 개인 대상 설계다.

## 9. 대표 확인이 필요한 항목

전환에 직접 영향이 있고, 값이 없으면 원고를 쓸 수 없는 것만 모았다. 데이브 B1~B8 · 수진 A1~A11 과 중복되는 항목은 그쪽 번호를 병기했다.

| --- | --- | --- | --- |
| **O1** | **코치 실명 · 자격 · 경력** (수진 A1과 연동) | **1:1 코칭에서 코치가 상품이다.** 지금 사이트 전체에 실제 사람의 근거가 0개다. 이 페이지가 열리는 시점이 전환율이 가장 크게 움직이는 시점이다 | `/coach` 를 `published:false` 로 유지. 신뢰 근거 없이 오픈 |

| **O5** | **FAQ 추가 질문 6~8개의 답** (§5.5) | 현재 4개로는 페이지 한 장이 안 된다. 그리고 FAQ 는 신청 직전 이탈 사유를 제거하는 가장 값싼 장치다 | `/faq` 를 4문항으로 열거나 미룬다 |
| **O6** | **세션 노트 빈 양식 이미지 1장** (§7.2-2) | 후기·사진이 전부 없는 상태에서 **오늘 확보 가능한 유일한 실물 근거**다. 개인정보 없는 빈 양식이면 된다 | 「기록으로 남긴다」가 말로만 남는다 |
| **O7** | **랜딩 카드 링크를 상세로 돌리는가** (수진 A11 · §3.4) | 랜딩의 상담 링크 11곳 → 4곳. **트랙 식별의 전제 조건**이다 | 트랙 구분이 헤더·푸터 유입에서만 가능해지고, 대표의 첫 통화가 지금과 같다 |
| **O8** | **`/service` 폐기** (C2 · §2.11) | 항목 4개 중 2개가 존재 미확정, 2개는 다른 페이지 내용. **O4 의 답에 따라 달라진다** | 빈 껍데기 페이지 한 장 |
| **O9** | **`/program/online` 을 여는가** (C3 · §2.7) | "프로그램"이 아니라 진행 형태다. 유지 근거는 SEO 하나 | 「온라인 코칭」 검색 유입 하나를 잃는다. 그것만 잃는다 |
| **O10** | **폼 전송을 페이지 공개 전에 붙이는가** (C1 · §7.3) | **되돌릴 수 없는 유일한 손실.** 유실된 신청은 복구할 수 없다 | 페이지 작업 전체가 0이 된다 |
| **O11** | **`/about` 의 브랜드 서사(창업 배경·계기)** (§5.3 ④) | 없으면 `story` 블록을 비운다. 브랜드명도 미확정인 상태에서 쓰면 창작이다 | `/about` 을 코칭 방식 설명(①②③)만으로 구성 |
| **O12** | **프로그램 진행 주기·회차** (§5.1 ④ · §5.2 ①) | `SpecList` 와 비교표의 핵심 행이다. O2(가격)와 묶여 있다 | `[대표 확인 필요]` 로 표시된 행을 비운다 |

**O10 → O1 → O2 순으로 확인이 급하다.** O10 은 손실이 되돌아오지 않고, O1·O2 는 페이지의 전환 기여를 결정한다.
